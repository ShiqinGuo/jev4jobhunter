# Boss 直聘网页适配

范围：`https://www.zhipin.com` 的求职者网页。路由与选择器是定位线索；2026-09-07 已用 Kimi WebBridge 实测搜索、滚动加载、沟通回执和简历编辑。仍以当前可见页面为准，不把一次实测的配额或机制当作所有账号的固定规则。

## 导航与读取

| 目标 | 历史入口 / 线索 |
|---|---|
| 职位列表 | `/web/geek/jobs`，也可从首页“职位”进入 |
| 搜索 | 站内搜索框“搜索职位、公司”，城市用可见筛选器选择 |
| 详情 | 从职位卡打开；历史链接形如 `/job_detail/<id>.html` |
| 消息 | `/web/geek/chat`，或顶部“消息”入口 |

职位可能是左侧列表、右侧详情的布局。选择卡片后重新观察详情，确认标题、公司、地点与当前卡片一致，再读全文。列表标签不能代替 JD。通过可见分页 / 滚动加载更多，无需调用私有接口。

搜索结果支持向下滚动继续加载。先识别实际职位列表的滚动容器，滚动后等待并读取新增卡片，以稳定职位 ID 比较前后覆盖；不要滚动右侧 JD 后误以为已加载列表。首屏没有合适项不代表结果耗尽，也不是换城市的理由。持续读取新批次；明确到底、平台提示、用户数量目标或加载停滞才结束当前查询。没有增长时先等加载完成并再滚动核验，仍异常则按故障恢复流程刷新。记录城市、关键词、已见 ID、末尾卡片和是否到底，便于中断后续查。

登录以当前可见账号、消息入口和登录提示综合判断。单独看到 URL 含 `_security_check` 不足以判定拦截；需结合空白内容、验证码或明确安全提示。

## 立即沟通与申请不是同一动作

- “立即沟通”可能发送平台预设招呼语、创建会话、弹确认层或提示额度。**点击本身视为外发**，事先登记 `greet` 动作；不能为了探测其行为先点击。
- 不要求用户开启自动招呼语，也不改平台设置。若已启用且当前可核对文本，检查它与本次授权内容一致；看不到将发送什么时先准备草稿。
- 点击后先读结果。平台已发招呼语时不要再手动补发 opener。只看到聊天页而没有成功证据则记 `unknown`；只有明确确认未发送才走新的受控发送步骤。
- 若弹出发送简历、交换联系方式等内容，按实际副作用重新核对用户授权。一个招呼授权不能自动扩成附件授权。
- 不默认招呼语上限为 300 字；读取当前限制或错误提示，生成满足限制的完整短版，不机械截断。
- 报告区分“已打招呼”“已发简历”和“已完成申请”，不要统称已投递。

## 聊天

1. 用“未读”筛选和页面最后消息发现变化。打开后核对公司、HR、关联职位；列表预览和日期不能独立判定新旧消息。
2. 读取足以覆盖问题的上下文，必要时滚动历史。同一天重复文本也可能是新消息；优先可见的消息 ID，否则组合作者、时间、文本和相邻消息位置生成 turn fingerprint，证据不足则暂挂。
3. 从顶部职位卡 / “查看职位”补充 JD。一个 HR 可能聊多个岗位，不能仅按 HR 姓名选上下文。
4. 用所选通道点击可见会话条目，读取实际打开的会话核对身份；旧版本点击失效的经验不代表当前通道不可用。
5. 只在已有授权及 `pending` 记录后填写编辑器；发送前检查文本和发送按钮可用。历史版本 Enter 会直接发送，不用 Enter 换行。
6. 新增的我方气泡文本、收件人、时间和送达 / 已读状态共同作为回执证据。输入框清空本身不算成功。

## 旧 DOM 提示（只在当前工具允许 DOM 时使用）

| 区域 | 历史选择器 |
|---|---|
| 职位卡 / 标题 | `.job-card-wrap` / `a.job-name` |
| 详情操作 | `.job-detail-op`，`a.op-btn-chat` |
| 会话条目 | `.friend-content-warp` 内的 `.friend-content` |
| 顶部职位卡 | `.top-info-content` |
| 消息历史 | `.message-content`；旧 `.chat-content` 实际是推荐联系人区域 |
| 消息气泡 | `li.message-item.item-friend` / `.item-myself` |
| 编辑器 / 发送 | `div.chat-input[contenteditable]` / `button.btn-send` |

不要要求这些选择器全部存在才允许读取；新账号无会话、详情尚未选中、页面懒加载都可能正常。

## 标识与失败处理

- 列表不继续加载时先核对滚动的是职位列表、加载状态和新增职位 ID。Kimi 实测后台 `document.visibilityState=hidden` 会使加载停滞，`Page.bringToFront` 不一定恢复；仅在通道允许 CDP 且观察到此情况时，可临时 `Emulation.setFocusEmulationEnabled({enabled:true})` 后正常滚动，收尾在 finally 恢复 `enabled:false`。这是加载恢复，不是绕过配额；正常加载时不额外开启。
- “还剩 N 次”是剩余额度提示，不是限额耗尽。读清确认层；确认后仍须看到发送回执才记成功。2026-09-07 某账号实测 150 次达到当日上限，仅作为带日期观察，不写死通用每日上限。
- 详情空白、点击无反应或筛选未更新，先自行刷新并重新核对账号、城市、关键词、职位及原动作状态。未提交动作可恢复执行；已经触发提交的动作只核对回执，无法确认则保留 unknown，禁止再次点击补发。

- 职位 key 优先 `boss:<详情链接中的稳定 ID>`。保留原始 URL 供复核，不存 cookie、签名参数或令牌。
- 线程 key 优先当前工具可见的稳定会话标识；拿不到时用公司、HR、职位和线程链接共同生成本地键，并记录 `identityConfidence: low`。不能仅因姓名相同合并；疑似重复先核对再发。
- “今日沟通上限”记录为该平台的 greet 限额；不要因此停止其他平台或把消息读取也关掉。验证码 / 登录验证则暂停该平台访问，待实际恢复后解除。
- 不点击与用户任务无关的收藏、举报、购买配额、设置、简历编辑等按钮。
