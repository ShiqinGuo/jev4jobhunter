# Kimi WebBridge 固定通道

## 接入与恢复

本插件所有招聘页面操作固定经 Kimi Browser Extension / Kimi WebBridge。先完成 SKILL.md 的压缩后恢复检查，读取当前环境的 kimi-webbridge 技能，遵守其实际 API 与会话规则。正式搜索和投递经 [browser_actions.py](../scripts/browser_actions.py) 单步入口，内部通过 [webbridge_client.py](../scripts/webbridge_client.py) 向 Kimi 本机 daemon 发送命令。

`policy.browser.required` 与兼容字段 `preferred` 均为 `kimi-webbridge`，`allowFallback` 为 `false`。旧配置只设置 preferred 时同样固定；未设置浏览器的新方案也使用此通道。`resume-context` 只读本地，不需要运行锁、session 或浏览器连接；输出断点和固定通道，不代表在线验证成功。`inspect` 等实际操作在传输前拒绝冲突配置。

Kimi session 是 Kimi daemon 的会话标识，不是 `cua.getTab` 的标签 ID。`mcp__cua_repl` / `cua.*` / computer-use / 自带浏览器均不属于 Kimi，不能用于状态探测、截图、恢复或任何其他页面步骤。即使都是同一个 Edge 窗口也不可互换；通道说明中的初始化要求只在确实选择该通道时适用，不构成改道授权。

复用本任务的 Kimi session，交接记录通道、session、账号归属和当前待核对动作。缺少 session 时仅通过 Kimi 正常会话接口找回本任务归属；不猜 ID，不接管其他任务。Kimi 不可用时保存断点、记录原因，继续本地工作；不自动重启正在工作的 daemon，也不探测备用浏览器。已提交但结果未知的动作只核对，不重发。

用 `inspect-session` 查看当前 session 的真实 URL、active 与 borrowed；`select-page` 从这份清单选唯一页面并核对实际返回 URL。2.0.9 实测 find_tab 即使收到完整 URL 仍可能返回同站点另一页，因此不能只检查 success。错页后按正式 `open-page` 进行普通站内恢复；保留原搜索批次。页面内真实点击打开的 borrowed 详情，仅在本 session 清单确认该详情 active 时按 active 选择，不借用其它用户标签。focus-page 返回的 visible 只证明当次观察，后续仍需检查。

通道说明允许 Python HTTP 传输时，入口内部使用 UTF-8 字节传输，不经 shell 拼接中文、不自动重试。不用裸 curl、循环 evaluate、CDP 或招聘平台私有接口绕过单步入口；登录等未适配动作保留材料和缺口。验证码等秘密输入只走当前工具允许的内存传递方式，不落入请求文件。不读取浏览器凭据或复制 cookie。

## 标签已关闭或当前页面丢失

`inspect` 的 browser-read-failed 会保留 cause.code/message。若 cause 表明 tab was closed / navigate first，先取得运行锁，沿用 resume-context 的原 Kimi session，执行 `browser_actions.py --data-dir DATA_DIR --token TOKEN --session SESSION --operation recover-page`；不要把纯观察失败当作一次未知外发。

该入口只查询本任务 Kimi 标签。已有唯一 BOSS 职位页时允许在保留访问限制的情况下被动重新选中，返回后仅 inspect 核对原账号；正常观察后仍须 clear-access-block 才能继续。不存在职位页时，访问限制仍禁止打开新页面。返回URL必须确属BOSS职位页；若Kimi误选其他标签，不沿用错误页面继续操作。旧查询、候选、成功和 unknown 不清空。初次创建恢复标签组时告诉用户页面集中在“求职投递”，只在用户要求时关闭。

不传任意 URL、不借用其它任务标签、不重启 daemon。未决 submit 先 reconcile 保留真实状态；导航结果未知时先查同一 session，不盲目重复打开。多个职位页无法唯一归属则保留现场说明。恢复不代表登录、筛选或投递已成功；出现访问限制仍停止。普通加载占位不是安全验证，明确安全检查/验证码仍按限制处理。

## 登录恢复

以下网页恢复步骤仅在当前版本对应的 Kimi 单步入口已适配时执行；未适配时保存所需材料和具体缺口，继续独立本地工作，不裸调用浏览器。已有登录授权继续保留，缺口不改写为缺少批准。

先读取本地平台限制。未到访问限制恢复条件时不触发登录、刷新或换账号测试，只可观察已加载页面；普通登录失效才走本节。先复用已有登录，确认目标账号；不要主动退出有效登录来测试。登录失效时按页面的正常流程恢复。只有用户已授权本人设备用于当前网站登录，且设备连接和短信读取能力已验证，才可使用 ADB 获取本次主动请求的验证码。限定网站、号码、请求后的时间窗与必要字段，验证码只用于当前表单，不写入日志、画像、状态或报告。多设备先确定授权设备；缺少连接、权限或可信匹配短信则交用户完成。

短信验证与页面验证分别记录能力和实际结果。用户授权本人账号登录时，可按当前浏览器工具允许的正常页面操作尝试完成可见拼图或滑块；依据截图定位并拖动，核对页面回执，不伪造验证结果或调用私有验证接口。实际操作失败、工具明确限制或要求本人身份确认时才保留现场交接。一次成功只证明本次流程，不保证未来每次无人值守成功。恢复后先核对 pending / unknown，不能重发未知动作。

### 已授权 Android 设备的锁屏短信

配置了 `policy.browser.androidConfig` 时，读取该个人设备配置及其 `skillPath` 指向的 Android 技能；未配置则不假定手机存在。ADB 命令、短信解析与断连恢复由 Android 技能负责，job-hunter 不复制另一套实现。设备路径、标识、授权与实测记录属于个人配置，不硬编码在插件。

用户已授权定时登录辅助时，正常登录失效可按页面请求本次验证码，调用 Android 技能在请求后的时间窗内匹配该站点短信。已授权且在线的设备即使锁屏、熄屏，也先尝试短信 provider；不因黑色截图或锁屏状态要求用户解锁、暂停整轮任务。仅使用当前请求的唯一验证码；历史短信验证记录不等于当前登录凭据。用当前浏览器通道填写并核验账号，随后续接原投递批次。

provider 空结果不等于未收到短信：部分手机把最新验证码放在短信应用卡片中。调用 Android 技能从会话列表按时间倒序检查本站点最新消息，跨同名发送方核对本次请求时间与用途；不能沿用当前已打开的旧会话或只看站点签名。多条本次有效消息选择时间最新且可确定属于当前请求的一条，时间或归属不明确就不填旧码。锁屏通知掩码不是验证码。确需解锁读取时，只按用户已授权范围使用个人配置中的加密凭据和 Android 技能的正常解锁流程；任务结束恢复本轮改变的锁屏状态，用户正在操作手机时保留其现场。插件不保存解锁凭据。

验证码只在必要传递过程中使用，不进入持久化文件或日志；遵守浏览器通道的秘密输入能力与文件传参限制。ADB 失联先按 Android 技能重新发现并核实同一授权设备；权限拒绝、身份无法确认或必须人工的人机验证分别记录阻断。网页登录有效时不请求验证码、不读取短信。日报等只读模式若需要会改变账号登录状态的恢复，使用已有数据报告缺口，等下一次已授权操作轮次恢复。

## 最小能力与可选增强

这些是 Kimi 通道的能力检查，不是备用通道清单，也不是可直接调用的 `driver.*` 函数。

| 能力 | 可用形式 | 缺失时 |
|---|---|---|
| 打开与导航 | 标签导航、打开 URL、点击站内链接 | 用户提供页面内容 / 链接供分析 |
| 观察 | 页面快照、无障碍树、可见 DOM 或截图 | 无法确认页面内容则不操作 |
| 定位与点击 | 实时元素引用、语义定位器、截图坐标 | 仍可读页面；不猜坐标 |
| 文本输入 | 工具原生 fill / type / paste | 只准备草稿 |
| 滚动与等待 | 原生滚动、等待元素 / 下一次观察 | 先观察已加载区域，再决定是否继续 |
| 文件上传（可选） | 工具暴露的上传 / 文件选择器 | 准备附件与答案，请用户完成上传 |
| JavaScript（可选） | 工具明确允许的可见 DOM 读取 | 用已有页面快照或截图继续只读分析 |
| 截图保存（可选） | 宿主提供的截图输出 / 附件 | 记录可得的文字证据，不编造路径 |

某项 Kimi 能力缺失只限制相应操作；正式入口尚未适配时保留材料，不能临时换通道实现。

## 操作纪律

- 通道固定规则适用于本插件；历史旧版的宿主浏览器优先或备用通道规则已失效。账号、站点或页面变化要重新核验当前 Kimi 现场，不能自动换浏览器。
- Kimi 截图像素与 CDP 鼠标坐标可能不同：从当前视口与截图尺寸核对缩放比例，CDP 使用 CSS 像素。窗口缩放或布局改变后重新观察，不能沿用旧截图坐标。连续页面动作应依据实际回执，不用长串高延迟工具调用代替单次必要操作。

- 复用用户指定的标签；否则按 Kimi 技能创建任务标签，记录哪些是自己创建的。不要拿固定 session 名去控制其他任务的页面。
- 每个操作基于刚观察的页面。导航、切会话、滚动虚拟列表、打开弹窗后重新取快照；旧 ref / 坐标不能跨页面复用。被动读取已加载 DOM 或截图本身不计作新增页面请求；禁止在观察代码中夹带 fetch、导航、滚动或点击。
- 优先语义定位器或工具元素引用。CSS 只在工具允许且已从当前 DOM 观察到时使用；旧选择器只是定位提示。
- 使用所选通道提供的填写与点击；无需随机延迟或拟人轨迹。允许工具内部按自身方式输入，基于可见结果判断成功。
- 富文本填写后确认实际文本。未经验证不靠 Enter 提交，多行文本交给输入工具；发送按钮也必须先确认目标。
- DOM 读取能力不等于任意 JS 执行权限。不能从 React/Vue 隐藏状态、内部全局变量、网络资源或逆向接口补取不可见数据。主流程不依赖招聘网站私有 API。
- 等待使用工具支持的加载 / 可见性条件或下一次观察，不设长时间固定 sleep，也不靠随机延时或固定秒数宣称安全。读取失败先被动观察并区分普通加载与平台限制；发送后超时先核对回执。当前批次未处理完不滚动预取。用户授权集中阅读时，正式 collect-details 可在保存完整详情证据后顺序读取组内下一条，统一判断后逐个发送；其他情况仍先收尾当前详情和外发。

## recon 的可交付结果

记录本次使用的宿主工具、浏览器 / 标签、平台、账号可见标识（最少必要信息）、检查时间，以及下面的结果：

- 登录 / 验证状态是否明确。
- 能否搜索并打开一个职位，读到真实 JD；零搜索结果是正常业务结果。
- 若本次涉及回复，能否打开一个已有会话并读上下文。新账号无会话记为“尚未验证”，不判定为改版。
- 输入 / 上传 / 提交能力哪些已知、哪些未验证。recon 不通过试发消息验证它们，也不填消息编辑器；搜索框可以填写。

结果用 `available / unavailable / unverified` 加原因，不把“未验证”写成“已跑通”。未知网站仅在对应 Kimi 单步入口已经适配时继续正常导航和明确表单；未适配则记录缺口。真正含糊的外发按钮需停当前动作。
