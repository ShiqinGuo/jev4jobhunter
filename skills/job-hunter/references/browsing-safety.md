# 页面浏览安全策略

用于所有招聘平台的正式搜索、详情阅读和投递流程。目的是真实减少不必要的页面访问，并按平台页面的交互顺序推进；不以随机延时、鼠标轨迹或固定等待秒数伪装人工操作，也不承诺某个节奏不会触发平台限制。

## 先筛选，再逐项处理当前列表

1. **先在平台设置条件。** 把当前策略中平台能够表达的硬条件设置到可见筛选器，例如城市、经验、薪资、学历或职位类型；读回已选项和结果页，确认筛选生效后再读岗位。不能仅凭 URL 参数、点击成功或旧状态判定生效。平台不能表达的条件才留到列表或 JD 判断；未在策略中明确配置的软参考不能擅自变成硬筛选。
2. **只处理当前自然加载的列表。** 读取当前页面实际加载的新卡片，先按稳定职位 ID 与成功、pending、unknown、历史联系记录去重，再用列表显示的城市、经验、岗位方向和明确排除项粗筛。记录排除、进入详情或待确认及其依据；列表已明确不符的岗位不再打开详情。平台每次实际加载多少就处理多少，不写死 15 条等数量，也不预加载几批后一起筛选。
3. **一次只打开一个候选详情。** 该岗位必须来自当前列表且通过粗筛。通过卡片的正常入口打开独立详情页面或平台原有详情面板，核对岗位身份后读全文。列表标签只决定是否值得打开；详情按用户允许的年限范围及独立身份条件判断，具体见 matching.md，不能以本人实际工龄覆盖已明确的试投范围。记录推荐、排除或待确认后，合适且已授权的岗位完成准备、检查、登记、操作和回执核验，再处理下一项。待确认可以暂挂，不必阻塞其他岗位；结果未知的外发保留 unknown，不能再次提交。
4. **当前批次完结后才加载下一批。** 所有当前卡片都有去向、当前详情已作出判断、可能的外发已核验或保留未知后，才允许对实际职位列表滚动一次。等待加载状态和实际新增 ID；拿到新增项就回到列表粗筛，不继续滚动预取。滚动距离按当前视口与页面确定，不修改 pageSize、cursor 或其他内部参数。没有新增时先观察加载与末尾提示，按普通故障边界有限恢复；不能连续滚动、刷新或开标签直到数量变多。
5. **查询受用户条件约束。** 只使用 policy.search.queries；用户指定固定平台筛选时保持 selectedLabels 的完整集合。只有已授权多个查询且当前查询确实结束时，才进入下一个允许词；用户的新更正则立即收尾旧候选并切到新条件。列表低通过率、本批完成和暂时无新增都不授权换词或改筛选。保存已见 ID、筛选条件、当前批次和逐项去向，中断后继续。

“批量投递”仅表示本轮成功数量和查看消息的间隔，不授权批量抓取详情。禁止 `details(岗位数组)`、`load(N)`、循环导航后统一筛选、并行详情请求、多标签预取、读取隐藏应用状态、私有接口或扩大平台分页。不同页面布局不改变上述顺序。

详情读取中断后先被动 inspect 当前已加载页面，不默认重新打开。若仍无法确认原 open-detail 已完成，`defer-detail(key, evidence)` 只把这个读取候选暂挂；它要求该步骤之后的新观察，不再点击，也不能用来取消已发送动作。submit 中断继续走原 outbox 的 reconcile，没有匹配回执保留 unknown，禁止重发。进程在 begin 后、浏览 submit 登记前退出时，使用 browsingContext 关联原候选并收尾，不能留下 apply 候选后重新提交。

当前批次可能超过一个视口。处理完后每次滚动一个视口，再观察与 capture-list；已处理卡片后有反馈卡或页脚时，即使 listTailBelowViewport=false，实际滚动容器仍有 scrollRemaining，也应继续同一查询的下一屏。一旦新增 ID 出现先处理新批次，不滚动预取。

没有新增但仍在加载时等待后被动观察；已到实际滚动底部仍无新增时，`finish-list-read` 只结束这次等待，不证明查询耗尽、不授权换词。没有限制提示可在同一查询做一次有依据的加载恢复并观察；仍无进展则保存“加载未确认”的断点，继续不依赖它的任务，后续轮次从这里恢复。页面明确显示结束才能记结果耗尽，不能仅凭滚动几何位置、工具成功或短时无新增宣称已搜完。普通逐屏推进与无依据反复刷新不是同一种操作。

悬停展开的原生筛选器可通过 `control` 的 `interaction: "hover"` 操作。入口只将指针移动到当前观察到的唯一可见筛选菜单中心，再观察选项；不伪造选中状态、不点击隐藏选项。命令结果未知时保留步骤，先被动核对，不自动重复。

上一观察存在的选项若在下一次操作前收起，可在相同菜单内有界重新展开一次；这不放宽查询条件，也不适用于外发重试。deferred 不是永久排除：候选再次自然可见时用 revisit-candidate 复审，保留之前证据，并重新进行列表及详情判断。跨页面恢复保留原批次或未完成队列，不能用重新配置查询清空未完成项。

## 页面异常先分类

| 当前证据 | 允许的后续操作 |
|---|---|
| 普通加载、定位或筛选更新失败，没有限制提示 | 先观察当前已加载页面，确认原因后按原流程有限恢复；恢复一次仍失败则保存断点 |
| 今日新沟通配额耗尽 | 停止对应发送种类；其他已授权操作仍须通过各自检查 |
| 明确访问受限、异常行为、安全验证，或无法解释的异常等待页 | 停止该平台的新导航、滚动加载、刷新、详情打开和外发，保存当前证据与限制状态 |
| 已加载页面、截图和本地日志 | 可以被动读取用于诊断和对账；不得为了“只读”触发新页面请求 |

HTTP 200、浏览器命令返回成功或 URL 未改变都不能证明页面正常。不能把“请稍候”等没有正文的异常页自动当作普通加载失败并继续批量读取。页面空白本身也不证明封禁，应结合当前可见提示和加载状态；无法解释时先停当前平台的新请求。

被动观察指读取已经加载的 DOM、可见快照或截图，不点击、滚动、导航、刷新或执行网络访问。纯 DOM 读取不应被统计为新增平台请求；实际页面操作次数也不能冒充已观测到的 HTTP 请求数。

## 限制与恢复跨轮次保留

每轮、每次心跳在接触浏览器前先读本地限制状态。记录平台提示、观察时间、受影响动作和平台给出的最早恢复时间；未到恢复时间不访问试探，不因跨日、新运行或重新登录自动清除。页面仍受限就保留限制，不循环试探；没有明确恢复条件时不能自行编造解禁时间。首版入口不主动刷新试探解禁：当前原账号页面已经通过正常流程恢复后，先 inspect 取得正常页面证据，再用本地 `clear-access-block` 核对账号、session、证据和最早恢复时间后解除；到期本身不足以清除限制。

访问限制按已核验的账号上下文和适用范围生效；发送配额只覆盖对应发送。换标签或浏览器不会解除原账号的限制。旧版只按平台记录的限制不能无条件推断为另一独立账号也受限：用户明确说明是独立新账号，且当前运行、当前会话的被动观察显示该账号页面正常时，使用 `select-account-context` 记录明确上下文 ID、显示名、声明和页面证据，把旧未绑定记录归属原上下文。旧限制仍 active，原账号再次被选中仍受阻；这一步不宣称旧账号已恢复，也不凭显示名猜网站唯一账号 ID。

新上下文出现的真实限制立即保存到该上下文并停止后续操作。页面出现 IP 文案时记录 `reportedScope: "ip"`，它描述平台原文，不凭一次旧观察推断永远适用于所有账号。已明确核验适用于共享环境的限制记录 `applicability: "all-contexts"` 和 `scopeEvidence`，或明确 `appliesToContextIds`；该范围内的上下文仍受阻，不能用声明新账号解除。未进行明确归属的旧限制继续生效，不因仅修改显示名、查询或 session 自动失效。

上下文选择不改个人资料和 policy，不清理成功、pending、unknown、历史联系记录，防重键也不增加账号字段以规避旧投递。新账号采用不同资料和筛选条件时要保存独立、可核对的配置；独立数据目录必须保留来源与适用限制，并继承相关外发防重记录，不能用空目录抹掉未知发送。存在 pending 外发时先对原动作核对结果，再切换上下文。

## 正式入口与能力边界

正式浏览器流程统一使用 [browser_actions.py](../scripts/browser_actions.py) 的单步语义入口，由 [browsing_safety.py](../scripts/browsing_safety.py) 保存筛选、当前列表、单个详情、限制和恢复断点。原有 [store.py](../scripts/store.py) 继续负责运行锁、授权、外发防重及回执；浏览安全状态不替代外发状态机。

浏览能力与业务约束分别检查：搜索要求原生筛选、自然批次、逐条详情与去重；已有聊天要求账号、收件人、最新来消息、授权和回执，不要求先完成搜索批次。普通回复和平台简历分享走正式聊天入口。新 UI 的单项 unsupported 不代表整个功能无授权；明确的插件维护任务应补齐适配并验证。详见 [runtime.md](runtime.md)。

入口应检查当前步骤的前置条件，再交给所选通道执行一个实际页面动作；回传观察结果后才推进下一步。禁止在一次通用 evaluate、CDP 或临时脚本里隐藏多个详情导航、滚动或外发动作。平台特有判断由实时页面证据支持，不能为了通过检查编造已筛选、已读详情或已恢复。

[webbridge_client.py](../scripts/webbridge_client.py) 是传输实现，不是独立安全入口。正式搜索和投递不直接调用它或裸 curl；不得改用自带浏览器或其它通道；所有网页观察与操作固定走 Kimi。若当前入口不能表达所需操作，保存断点和具体缺口，不能退回无检查的批量脚本。

这些检查约束经过正式入口的执行，不是浏览器沙箱：它们不能拦截任意外部 curl、用户手动操作或另一个未接入入口的脚本。文档规则、脚本已执行的检查、模拟测试和真实网站验证分别报告，不把新增模块或本地测试通过写成网站已验收。
